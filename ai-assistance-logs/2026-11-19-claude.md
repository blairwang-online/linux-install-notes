## 7. LLM response

I'll check Forgejo's built-in HTTPS settings and its certificate-generation command before writing this up.

Yes. Forgejo can serve HTTPS itself, so you don't need a reverse proxy: Set in SERVER section of the configuration PROTOCOL=https and either set CERT_FILE and KEY_FILE. It also has a built-in `forgejo cert` command that makes the self-signed certificate. I've added a section on this to `tasks/forgejo-podman.md`. It isn't tested on a running server yet.

**The three steps**

1. **Generate the certificate inside the container.** `forgejo cert` writes to 'cert.pem' and 'key.pem' and will overwrite existing files, and `--host` takes Comma-separated hostnames and IPs to generate a certificate for. The doc runs it in `/data/gitea/https`, so both files end up in `/srv/forgejo/gitea/https/` on the host, for the names `myserver.local` and `myserver`.
   - By default the certificate is valid for one year (Value: 365 * 24 * time.Hour). The doc uses `--duration 43800h` (five years) so you're not re-importing it on every client each year. Browsers' 398-day limit only applies to certificates from public certificate authorities.
   - Don't use `--ca`. Firefox rejects a CA certificate used directly as a server certificate.
2. **Change `forgejo.container`.**
   - Set `PROTOCOL=https`, point `CERT_FILE` and `KEY_FILE` at the generated files, and change `DOMAIN` and `ROOT_URL` to `https://myserver.local/`.
   - Publish 443 to Forgejo's port 3000, so the address needs no port number.
   - Turn on Forgejo's built-in HTTP-to-HTTPS redirect: when `REDIRECT_OTHER_PORT` is true, it allows redirecting http requests on `PORT_TO_REDIRECT` to the https port Gitea listens on. In the doc that runs on 3080 inside the container, mapped to 80 on the host.
   - In the firewall, open `https` and `http` and close 3000.
3. **Trust the certificate on each client, once.** The doc has a one-line command for each of AlmaLinux/Fedora, Debian/Ubuntu, Windows and macOS, plus Firefox on Linux, which keeps its own list. Git for Windows uses the Windows certificate store, so importing there covers it. Elsewhere you can trust the certificate for Git and this one server only with `http.https://myserver.local/.sslCAInfo`, rather than turning off certificate checking.

**Things to know**
- Copy only `cert.pem` to clients. `key.pem` stays on the server.
- Git over SSH on port 222 isn't affected. Existing clones need their remote changed to the new `https://` address; the doc gives the command.
- Once this is set up, Forgejo has ports 80 and 443 to itself. If you later want your Flask apps on 443 too, that's the point to put a reverse proxy in front. A proxy with its own internal certificate authority, such as Caddy with `tls internal`, would also spare you re-importing certificates on clients when they renew.

The updated repo is in `linux-install-notes.zip`.

**Cursed knowledge:** nothing new this turn. The Firefox `--ca` problem is a known one, and the setup avoids it rather than having run into it.
